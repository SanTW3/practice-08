# Вариант 21

cancel из APPROVED проверяет today.plusDays(3).isAfter(start). Ровно три дня разрешены, два запрещены. addDaysUntilStart реализует указанную формулу start.compareTo(today); это не универсальная разность дней.

## Решение 1
Правило расположено внутри доменного объекта, поскольку только этот объект отвечает за собственные инварианты и управляет изменяемыми полями. Сервис координирует создание объектов, а SelfCheck выполняет ввод и проверку результатов. Если перенести правило только в интерфейс, другой вызывающий код сможет его обойти. Поэтому все способы использования приложения проходят через одну и ту же проверку.

## Решение 2
Перегрузки с LocalDate today обеспечивают воспроизводимые тесты; методы без аргумента используют текущую дату.

## Ответы на контрольные вопросы

### Какая проверка защищает от ошибки входных данных
start.isAfter(end) вызывает IllegalArgumentException. Равные даты разрешены: командировка длится один календарный день. unit/4–5. Проверка выполняется до изменения состояния объекта. Это особенно важно при вводе данных вручную и чтении CSV: ошибка одной строки не должна создавать некорректный объект или повреждать ранее обработанные данные. SelfCheck проверяет как допустимые значения, так и ошибочные и граничные случаи. Исключение перехватывается на уровне интерфейса, после чего пользователь может исправить ввод и продолжить работу.

### Как диаграмма соответствует коду
submit требует DRAFT. Первый вызов даёт SUBMITTED, повторный вызывает IllegalStateException. unit/6–7. Узел проверки на диаграмме соответствует условию в методе, ветка отказа соответствует исключению, а успешная ветка заканчивается изменением состояния. Порядок узлов важен: присваивание выполняется только после успешной проверки. Так можно вручную проследить конкретный сценарий и сопоставить ожидаемый путь с тестом. Диаграмма показывает бизнес-операции, а не каждую строку синтаксиса Java.

Для демонстрации заменить MIN_REASON_LENGTH=10 на 20, обновить причины в тестах и CSV; проверить 19 и 20. Меняются бизнес-константа и тестовые данные, сервис не меняется. Изменение локализовано благодаря именованной константе и отсутствию дублирования бизнес-условия в сервисе и интерфейсе. Кроме реализации необходимо согласованно обновить тестовые ожидания и примеры входных данных. Проверки старой и новой границы подтверждают, что правило действительно изменилось. Для защиты такую модификацию следует показать отдельно, запустить SelfCheck, а затем восстановить исходное требование выбранного варианта.

## Таблица оценивания

### 1. Создание заявки
BusinessTrip проверяет id до присваивания полей. Валидная заявка имеет DRAFT; пустой id вызывает IllegalArgumentException. unit/1–3.

### 2. Проверка дат
start.isAfter(end) вызывает IllegalArgumentException. Равные даты разрешены: командировка длится один календарный день. unit/4–5.

### 3. Отправка
submit требует DRAFT. Первый вызов даёт SUBMITTED, повторный вызывает IllegalStateException. unit/6–7.

### 4. Согласование
approve требует SUBMITTED. submit → approve даёт APPROVED; прямое согласование DRAFT запрещено. unit/8–9.

### 5. Отклонение
reject сначала проверяет статус, затем причину. «Недопустимо» принимается, «Нет» отклоняется. Статус и причина меняются только после всех проверок. unit/10–12, 18.

### 6. Отмена
cancel разрешён из DRAFT и SUBMITTED. Из APPROVED по варианту 21 требуется минимум три дня до start; терминальные состояния запрещены. unit/13–14, 19–20.

### 7. Завершение
complete требует APPROVED и today >= end. При ранней дате выбрасывается IllegalStateException. unit/15–17.

### 8. Инкапсуляция
status и rejectionReason private, публичного setStatus нет. Переходы выполняют только доменные методы с проверками.

### 9. Enum
TripStatus содержит DRAFT, SUBMITTED, APPROVED, REJECTED, CANCELLED, COMPLETED. Сравнение enum через == проверяет единственный экземпляр константы.

### 10. Неизменяемые поля
id, start, end объявлены final. LocalDate и String неизменяемы; status и причина меняются в рамках жизненного цикла.

### 11. Сервис
BusinessTripService.create сохраняет заявку; findByStatus(DRAFT) возвращает обе созданные заявки. Переходы остаются в BusinessTrip, поскольку объект знает собственное состояние. unit/24.

### 12. Исключения
IllegalArgumentException означает неверные параметры: пустой id, даты, короткая причина. IllegalStateException означает недопустимую операцию в текущем состоянии.

### 13. LocalDate
start и end хранят календарные даты без времени и часового пояса. isAfter проверяет порядок дат, isBefore — возможность завершения.

### 14. Причина 10 символов
Условие reason.length() < MIN_REASON_LENGTH исключает 9 символов и принимает 10. unit/10, 23. null проверяется до обращения к length.

### 15. Дата завершения
today=end разрешена, today=end.minusDays(1) запрещена. Для воспроизводимости используется complete(LocalDate today). unit/15, 17.

### 16. Изменение требования
Для демонстрации заменить MIN_REASON_LENGTH=10 на 20, обновить причины в тестах и CSV; проверить 19 и 20. Меняются бизнес-константа и тестовые данные, сервис не меняется.

### 17. Data-driven
SelfCheck.data создаёт отдельную заявку для строки. OK сравнивает статус; ERROR сравнивает тип исключения действия; SKIP сравнивает ошибку конструктора. Составные действия разделены запятыми.

### 18. Интерактивный режим
sh run_selfcheck.sh --interactive; create T-01 2026-10-10 2026-10-12; submit; status. Вывод DRAFT, SUBMITTED, SUBMITTED. Команды вводятся отдельными строками.
